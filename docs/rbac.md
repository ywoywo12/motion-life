# الأدوار والصلاحيات (RBAC)

**مصدر الحقيقة:** `app/rbac.py`. الجداول `roles`, `permissions`, `role_permissions` تُملأ من الملف نفسه عند `seed`، لتكون مرجعاً للاستعلام والتدقيق. **التحقق يجري دائماً على الخادم** في طبقة الخدمات (`app/services/*`)، قبل أي قراءة أو كتابة. قوائم المرضى تُصفّى في استعلام SQL نفسه، ولا تُجلب كاملة ثم تُخفى في الواجهة.

## الأدوار

| الرمز | الدور |
|---|---|
| `DIRECTOR` | المدير العام/السريري |
| `DEPT_HEAD` | رئيس قسم (رجال/نساء) |
| `DEPUTY_HEAD` | نائب رئيس القسم |
| `THERAPIST` | معالج |
| `RECEPTION` | استقبال |
| `ACCOUNTING` | محاسبة |
| `SYSADMIN` | مسؤول النظام |

## نطاق الوصول للمريض

دالتان أساسيتان: `can_view_identity(user, patient)` و`can_view_clinical(user, patient)`.

| الدور | الهوية والتواصل | البيانات السريرية |
|---|---|---|
| DIRECTOR | كل المرضى | كل المرضى (التفويض الافتراضي في V1، مع تدقيق كل وصول) |
| DEPT_HEAD | مرضى أقسام عضويته | مرضى أقسام عضويته |
| DEPUTY_HEAD | مرضى أقسام عضويته | مرضى أقسام عضويته (اطلاع وإشراف). **الاعتماد فقط بتفويض نشط** |
| THERAPIST | المرضى المخصصون له (تخصيص نشط) | المرضى المخصصون له فقط |
| RECEPTION | كل المرضى (للتسجيل ومنع التكرار) | **لا شيء**: لا تاريخ طبي، لا فحوص، لا خطط، لا جلسات |
| ACCOUNTING | كل المرضى (هوية مختصرة) | **لا شيء**، فقط الباقات والدفعات |
| SYSADMIN | **لا شيء** افتراضياً | **لا شيء** (الوصول الاستثنائي غير منفذ في V1، ومؤجل مع تدقيق) |

## العمليات

| العملية | من يستطيع | شروط إضافية على الخادم |
|---|---|---|
| إنشاء مريض/تعديل الهوية | RECEPTION, DEPT_HEAD, DEPUTY_HEAD, DIRECTOR | فحص التكرار (اسم+تاريخ ميلاد / هاتف) |
| تخصيص معالج / نقل قسم | DEPT_HEAD (لقسمه), DIRECTOR | النقل يتطلب سبباً ويُدقّق |
| فتح حلقة علاج | THERAPIST المخصص، DEPT_HEAD/DEPUTY للقسم، DIRECTOR | — |
| إدخال التاريخ الطبي | THERAPIST المخصص، رؤساء القسم، DIRECTOR | الاستقبال **لا** يُدخل التاريخ الطبي في V1 (لا يقرأه، فلا يكتبه) |
| التقييم/الفحص | THERAPIST المخصص، DEPT_HEAD/DEPUTY، DIRECTOR | تعديل المدير أو الرئيس لنتيجة معالج يُسجَّل كتعديل موثّق باسمه وسببه |
| إنشاء/تعديل مسودة خطة | THERAPIST المخصص، DEPT_HEAD، DEPUTY | فقط في حالة `DRAFT`، ومن المؤلف أو مشرف القسم |
| إرسال للمراجعة | مؤلف المسودة | التقييم منتهٍ، أهداف ≥1، السلامة ليست ناقصة أو إسعافية، بنود الأجهزة موثّقة الموانع، قيود الجراحة موثّقة إن وجدت جراحة |
| اعتماد/إعادة/تصعيد/تعليق | DIRECTOR؛ DEPT_HEAD لقسمه؛ DEPUTY_HEAD بتفويض نشط | **ليس مؤلف الإصدار**. الحالة المصعّدة يقررها DIRECTOR فقط. الاعتماد يتطلب سلامة غير إسعافية وغير ناقصة، والإقرار بكل التنبيهات المفتوحة بملاحظة |
| تسجيل جلسة | THERAPIST المخصص، رؤساء القسم | يوجد إصدار `APPROVED`، والحلقة ليست معلّقة، والبنود من الخطة (أو «تعديل مؤقت» مبرر يرفع علامة مراجعة) |
| إعادة تقييم 6/12 | كمن يسجل الجلسة | — |
| التقارير | من يملك الوصول السريري للمريض | المحاسبة تطبع كشف الدفعات فقط |
| الباقات والدفعات | ACCOUNTING, DIRECTOR | المعالج لا يرى المبالغ |
| المستخدمون والتفويضات | SYSADMIN (حسابات وأدوار عدا DIRECTOR), DIRECTOR | **لا أحد يغيّر دوره بنفسه**. التعطيل بدل الحذف |
| التفويض بالمراجعة | DEPT_HEAD (لنائبه في قسمه), DIRECTOR | قابل للإلغاء ويُدقَّق |
| الكتالوجات | DIRECTOR (نشر)، DEPT_HEAD (اقتراح مسودة) | النشر يتطلب مراجعاً غير منشئ المسودة |
| سجل التدقيق | DIRECTOR, SYSADMIN (أحداث أمنية فقط، دون تفاصيل سريرية) | — |

## الحماية التقنية

- كلمة المرور مخزنة بـ`scrypt` مع ملح عشوائي.
- قفل بعد 5 محاولات فاشلة لمدة 15 دقيقة، لكل اسم مستخدم ولكل عنوان IP، مع تأخير ثابت.
- الجلسة: رمز عشوائي 256 بت في كوكي `HttpOnly; SameSite=Strict` (و`Secure` في الإنتاج). يُخزن في قاعدة البيانات **مُجزّأً (SHA-256)**. ينتهي بعد 12 ساعة أو 60 دقيقة خمول.
- CSRF: كل طلب غير GET يحتاج رأس `X-CSRF-Token` أو حقل نموذج يطابق رمز الجلسة، إضافة إلى تحقق `Origin`.
- تعطيل الحساب يُبطل جلساته فوراً.
- معرّفات المرضى والحلقات والخطط UUID عشوائية.
- لا تُسجّل أجسام الطلبات في السجلات. الأخطاء تُعاد برسالة عربية عامة ورقم مرجعي.
