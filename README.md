# Motion Life Clinical System — V1

نظام ويب عربي (RTL) لمركز **Motion Life للعلاج الفيزيائي وإعادة التأهيل** في دمشق. يغطي رحلة المريض لمجال **أسفل الظهر**:

تسجيل → تاريخ طبي متفرّع → فرز سلامة → فحص → أهداف وخطة → مراجعة واعتماد من مستخدم آخر مخوّل → جلسات مرتبطة بإصدار الخطة → إعادة تقييم بعد الجلسة 6 و12 → تقارير PDF عربية.

> ⚠️ **ليس جاهزاً للاستخدام مع مرضى حقيقيين بعد.** راجع قسم «قبل الاستخدام الفعلي». جميع البيانات التجريبية وهمية.

---

## التشغيل المحلي

**المتطلبات:**
- Python 3.11+
- PostgreSQL 14+ (اختُبر على 16)
- Chromium عبر Playwright (لملفات PDF)

```bash
# 1) الحزم
python3 -m pip install -r requirements.txt
python3 -m playwright install chromium        # على Linux: --with-deps

# 2) قاعدة البيانات (مثال)
sudo -u postgres psql -c "create role ml_app login password 'ml_app_dev'"
sudo -u postgres psql -c "create database motionlife owner ml_app"
sudo -u postgres psql -c "create database motionlife_test owner ml_app"   # للاختبارات فقط

# 3) الإعدادات
cp .env.example .env            # عدّل DATABASE_URL وSECRET_KEY

# 4) إنشاء الجداول والبيانات المرجعية والحسابات التجريبية
python3 -m scripts.migrate
python3 -m scripts.seed           # يطبع كلمة مرور الحسابات التجريبية
python3 -m scripts.demo_data      # اختياري: سيناريو تجريبي جاهز

# 5) التشغيل
python3 run.py
```

افتح **http://127.0.0.1:8000** في المتصفح.

### الحسابات التجريبية

كلمة المرور لجميعها: `Motion-Demo-2026`. هي حسابات للتطوير فقط، و`seed` يرفض إنشاءها في الإنتاج.

| المستخدم | الدور | القسم |
|---|---|---|
| `director` | المدير العام/السريري | الكل |
| `head.men` / `head.women` | رئيس قسم الرجال / النساء | — |
| `deputy.men` | نائب رئيس قسم الرجال | لديه تفويض مراجعة تجريبي |
| `therapist.a` / `therapist.b` | معالج | قسم الرجال |
| `therapist.w` | معالجة | قسم النساء |
| `reception` | استقبال | هوية وتسجيل فقط |
| `accounting` | محاسبة | باقات ودفعات فقط |
| `sysadmin` | مسؤول النظام | حسابات، دون سجلات صحية |

### سيناريو التجربة: مريض جديد ← فحص ← مراجعة ← اعتماد ← جلسة ← تقرير

1. **التسجيل:** ادخل بـ `reception`، ثم «المرضى» ← «تسجيل مريض جديد». جرّب إدخال اسم موجود لترى منع التكرار.
2. **التخصيص:** ادخل بـ `head.men`، وافتح المريض ← خصّص `المعالج أ`.
3. **التاريخ الطبي:** ادخل بـ `therapist.a`، وافتح المريض ← «التاريخ الطبي». كل إجابة تُحفظ فوراً، وشريط الحفظ أسفل الشاشة يبيّن الحالة.
4. **التقييم:** من صفحة المريض «فتح حلقة وبدء التقييم»، ثم الخطوات:
   - **2. السلامة:** أجب على كل سؤال صراحةً. جرّب «غير معروف» لترى المنع، أو «نعم» على خدر السرج لترى المسار الإسعافي.
   - **3. الأعراض:** اختر «أسفل الركبة» لترى المسار العصبي يظهر.
   - **4. الفحص:** تظهر الاختبارات المستطبة. كل اختبار له نتيجة أو «لم يُجرَ» مع السبب.
   - **5. الأهداف:** أضف هدفاً وقياس بداية.
   - **6. الملخص:** «إنهاء التقييم».
5. **الخطة:** «الخطة» ← أدخل الانطباع والبنود ← «حفظ المسودة» ← «إرسال للمراجعة».
6. **المراجعة:** ادخل بـ `head.men` ← «المراجعات» ← راجع الأدلة ← علّم «راجعت الأدلة» ← «اعتماد» (أو «إعادة للتعديل» مع تعليق لكل بند). جرّب الاعتماد بحساب الكاتب نفسه لترى الرفض.
7. **الجلسات:** بحساب المعالج ← «الجلسات» ← سجّل الجلسة. بعد 6 جلسات تظهر «مراجعة الجلسة 6» مستحقة.
8. **التقارير:** «التقارير» ← الملف الطبي، التقييم، الخطة المعتمدة (مع اسم المعتمِد وتاريخه وإصدارها)، الجلسات، الملخص الدوري، ملف المريض.

جاهز في السيناريو التجريبي (`demo_data`):
- **سامر:** مسار كامل حتى الجلسة 6 ومراجعتها.
- **خالد:** تقييم قيد الإنجاز مع إشارة سلامة تحتاج مراجعة (تاريخ سرطان).
- **ريم:** مريضة جديدة لتجربة المسار بنفسك.

## ما يعمل في V1

- دخول آمن:
  - كلمات مرور scrypt.
  - قفل بعد 5 محاولات.
  - جلسة في قاعدة البيانات بكوكي HttpOnly/SameSite=Strict.
  - CSRF + Origin.
  - CSP صارم.
  - انتهاء الجلسة بالخمول.
- **الصلاحيات على الخادم وفي الاستعلامات:**
  - المعالج يرى مرضاه المخصصين فقط.
  - رؤساء الأقسام يرون قسمهم.
  - الاستقبال والمحاسبة بلا بيانات سريرية.
  - مسؤول النظام بلا سجلات صحية.
  - لا اعتماد ذاتي (مفروض أيضاً بقيد في قاعدة البيانات).
  - تفويض نائب الرئيس قابل للإلغاء.
  - نقل القسم موثّق.
  - التعطيل بدل الحذف.
- **المرضى:** رقم ملف فريد، كشف التكرار (اسم مطبّع/هاتف)، بحث، حلقات علاج منفصلة لكل مشكلة، مرفقات محمية (PDF/صور) خارج المجلد العام.
- **التاريخ الطبي:** مطابق في تغطيته للنموذج الورقي (الأقسام 2–16):
  - كل سؤال بقيم «غير معروف/لم يُسأل/لا ينطبق».
  - مصدر الإجابة وتاريخها.
  - الاحتفاظ بكل قيمة سابقة.
  - جداول العمليات والأدوية.
  - تأكيد مراجعة الفريق.
- **فرز السلامة:** محرك قواعد حتمي يبيّن «لماذا» و«ما الذي لم يُسأل»، مع المسار الإسعافي (تعليق آلي) والتنبيهات وإقرار المراجع والإحالة الموثقة.
- **فحص أسفل الظهر:**
  - تفرعات: الألم الممتد/العصبي، الوقوف/المشي، الجراحة، الرضّ، الصور.
  - مكتبة اختبارات بإصدارات، مع حجب حسب السلامة.
  - شبكة عصبية لكل مستوى وجهة.
  - توثيق الحركات المتكررة.
  - أهداف قابلة للقياس.
  - قياسات بداية.
  - إصدارات تقييم.
- **الخطة:** مسودة منظمة (أجهزة/يدوي/صالة/منزل/تثقيف، بجرعة ومعايير تقدم وتوقف يدخلها المختص)، وإصدارات وحالات صارمة:
  - اعتماد، أو إعادة للتعديل مع تعليق لكل بند، أو تصعيد، أو تعليق وإحالة.
  - مقارنة الإصدارات.
  - تجميد المعتمد.
- **الجلسات:** مرتبطة بإصدار الخطة المعتمد. الإجراء خارج الخطة يحتاج مبرراً. الأحداث غير المرغوبة تنبيهات. مراجعات 6/12 بقياسات قابلة للمقارنة ونسبة تغير.
- **التقارير:** 6 تقارير PDF عربية من الخادم، وكل طباعة مدققة.
- **المكتبة العلاجية (`/library`):**
  - **149 تمريناً** برسوم توضيحية مولّدة (SVG) لـ22 منطقة جسم.
  - 10 أنواع: مدى حركة، إطالة، تقوية، ثبات، توازن، وظيفي، لياقة قلبية، تأهيل عصبي، تنفس، قوام.
  - **20 جهازاً** مع **البرامج المدمجة** المأخوذة من ملفات المركز: TR 31، BTL-4000 كهربائي 143، موجات فوق صوتية 57، SIS DUO 65، ليزر 42، Lymphastim 33، R-Force 29، FSWT 27.
  - في محرر الخطة: منتقٍ بالبحث والمنطقة والنوع، وجهاز ← برنامج. يُضاف البند بنقرة ويبقى قابلاً للتعديل.
  - تقرير **«برنامج التمارين للمريض»** PDF مع الرسوم.
- **الإدارة:** حسابات، أدوار، أقسام، تفويضات، كتالوجات بإصدارات (اقتراح ← نشر بمراجع آخر)، وسجل تدقيق غير قابل للتعديل أو الحذف.
- **المحاسبة المبدئية:** عدد الجلسات، المبلغ، أربع دفعات، المتبقي، كما في الملف الورقي.
- **الواجهة:** متجاوبة للهاتف والتابلت والكمبيوتر، عناصر لمس ≥44px، خطر يُميّز بالنص والأيقونة.
- **النسخ الاحتياطي:** `scripts/backup.sh` / `scripts/restore.sh`. **تم تنفيذ دورة نسخ ثم استعادة فعلية ومطابقة الأعداد.**

## ما لم يُنفّذ (مؤجل بوضوح)

- واجهة يملأ منها المريض الاستبيان بنفسه.
- التوقيع الإلكتروني للمريض.
- الإدخال الصوتي.
- الذكاء الاصطناعي.
- ربط الأجهزة.
- مناطق الجسم الأخرى.
- المواعيد والجدولة: غير ظاهرة في الواجهة، ولا أزرار وهمية لها.
- المحاسبة المتقدمة والفروع.
- المصادقة الثنائية (2FA).
- استعادة كلمة المرور بالبريد: حالياً يعيد مسؤول النظام تعيينها.
- الوصول الاستثنائي المدقق لمسؤول النظام.
- **برامج الأجهزة = أسماء البرامج المسبقة كما في ملفات المركز.** الملفات المرسلة لا تتضمن قيم الشدة والتردد والزمن، لذلك لا يخترع النظام قيماً: يضبطها المختص حسب دليل الشركة.
- الأجهزة التي لم تُرسل لها قوائم برامج تُضاف للخطة بإعداد يدوي: EMSELLA، Vac II، R-GAIT، Cryotherapy، CPMotion، R-Touch، DRX-9000، Kineo، HUR.
- مقاييس ODI/RMDQ: موجودة في الكتالوج **غير مفعّلة** لحين الترخيص.

## ملاحظات ومحدوديات معروفة

- **Python/Flask بدل Next.js/Prisma:** مستودعات npm وPyPI محجوبة في بيئة البناء. السبب في `docs/architecture.md`.
- **مشغّل قاعدة البيانات:** المختبر هو libpq عبر ctypes. مع `psycopg` (المفضّل للإنتاج) يُستخدم تلقائياً، لكنه **لم يُختبر هنا**.
- **Docker:** `Dockerfile` و`docker-compose.yml` **لم يُختبرا** (لا يوجد Docker daemon في البيئة).
- **طول ملف المريض:** يخرج في 4 صفحات A4 عند امتلاء البيانات، لا صفحتين كالنموذج الورقي.
- **نسخ النص من PDF:** بعض أدوات استخراج النص (مثل pdftotext) تعرض «لا» كـ«ال». العرض والطباعة سليمان.
- **مراجعة الجلسة 6/12:** تنبيه مستحق، وليست حجباً للجلسة التالية (قرار قابل للتغيير).
- **تعديل خلية في الشبكة العصبية** يُسجّل بسبب عام «تصحيح أثناء الفحص» مع اسم المعدِّل.
- **الخط:** لا خطوط تجارية مضمّنة. الواجهة تستخدم خطوط النظام العربية. في الخادم ثبّت `fonts-noto-core` لأفضل شكل في PDF.

## رابط تجريبي على Render (مجاني، ببيانات وهمية)

1. ارفع محتوى المجلد إلى مستودع GitHub (خاص).
2. في render.com: **New + ← Blueprint** ← اختر المستودع ← **Apply**. الملف `render.yaml` ينشئ الخادم وقاعدة البيانات تلقائياً.
3. انتظر انتهاء البناء (حوالي 10 دقائق في المرة الأولى)، ثم افتح الرابط `https://motion-life-trial-xxxx.onrender.com`.

ملاحظات:
- الحسابات التجريبية تُنشأ تلقائياً (`ALLOW_DEMO=1`). **لا تُدخل بيانات مرضى حقيقية في الرابط التجريبي.**
- الخطة المجانية «تنام» بعد 15 دقيقة دون استخدام، وأول فتح بعدها يأخذ قرابة دقيقة.
- قاعدة البيانات المجانية تُحذف بعد 30 يوماً.

## النشر

### Hostinger

بحسب صفحات الدعم الرسمية لـ Hostinger، **Flask/Python وPostgreSQL مدعومان على خطط VPS فقط**، وليس على الاستضافة المشتركة أو Web أو Cloud:
- [Flask](https://www.hostinger.com/support/?p=492)
- [PostgreSQL](https://www.hostinger.com/support/1583659-is-postgresql-supported-at-hostinger/)

**الخيار الموصى به:** VPS بنظام Ubuntu 24.04 (2 vCPU / 4GB RAM كحد أدنى مريح لـ Chromium).

```bash
sudo apt install postgresql python3-venv nginx certbot python3-certbot-nginx fonts-noto-core
python3 -m venv /opt/motionlife/venv && /opt/motionlife/venv/bin/pip install -r requirements.txt
/opt/motionlife/venv/bin/playwright install --with-deps chromium
# .env: ML_ENV=production, SECRET_KEY طويل عشوائي, COOKIE_SECURE=1, PUBLIC_ORIGIN=https://النطاق
/opt/motionlife/venv/bin/python -m scripts.migrate
/opt/motionlife/venv/bin/python -m scripts.seed --reference-only     # بلا حسابات تجريبية
# أنشئ حساب المدير الأول يدوياً (انظر docs/deployment.md)
/opt/motionlife/venv/bin/gunicorn -w 3 --threads 4 -b 127.0.0.1:8000 wsgi:app   # عبر systemd
# Nginx أمام التطبيق + شهادة HTTPS (certbot)، وتمرير X-Real-IP
```

- **بديل Docker** (غير مختبر): `docker compose up -d`.
- **إن لم يتوفر VPS:** لا يمكن تشغيل النظام على الاستضافة المشتركة. البديل خادم صغير داخل المركز، أو VPS لدى مزود آخر.

### النسخ الاحتياطي

- جدولة يومية لـ `scripts/backup.sh`.
- **نسخة مشفّرة خارج الخادم.**
- اختبار استعادة شهري إلى قاعدة منفصلة عبر `scripts/restore.sh`.

التفاصيل في `docs/deployment.md`.

## قبل الاستخدام الفعلي

1. **مراجعة سريرية:** يراجع مختص مخوّل ويعتمد أسئلة السلامة وقواعدها (`docs/clinical-rules.md`) ومكتبة الاختبارات وصياغة الأسئلة، ثم ينشرها من «الكتالوجات».
2. **مراجعة قانونية:** حماية البيانات الصحية والاحتفاظ والإقرار والموافقة حسب القوانين النافذة في سوريا. **لم ندّعِ أي امتثال قانوني.**
3. **الحسابات:** أنشئ حسابات حقيقية واحذف أو عطّل الحسابات التجريبية (أو لا تُنشئها أصلاً: `seed --reference-only`).
4. **الأمان:**
   - HTTPS إلزامي.
   - `SECRET_KEY` قوي خارج المستودع.
   - جدار ناري: قاعدة البيانات غير مكشوفة.
   - تحديثات النظام.
   - اختبار اختراق مستقل.
5. **النسخ الاحتياطي:** فعّل النسخ المجدول وخارج الموقع، وجرّب الاستعادة.
6. **التدريب:** على مفهوم «غير معروف ≠ لا»، والمسار الإسعافي، وعدم الاعتماد الذاتي.
